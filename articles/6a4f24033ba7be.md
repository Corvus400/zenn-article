# 初めに

フリーランスのAndroid開発者の[とだやま.R](https://github.com/Corvus400)です。本日(09/10)はDroidKaigi2025の[WorkshopDay](https://2025.droidkaigi.jp/timetable/9-10/)ですね。自分は例年どおり明日と明後日に参加します。

毎年恒例ですが、今年も開催の約1ヶ月前に公開されるカンファレンスアプリへ継続してコントリビュートしました。ただ今年は少し事情が違いました。リポジトリの公開はいつもの1ヶ月前ではなく[24日前の08/17](https://x.com/kitakkun_pb/status/1957012502803542059)で、貢献できる期間が例年より一週間ほど短かったのです。その制約のなかで何を狙い、どう動いたのかを書きます。去年の記事は[DroidKaigi2024のカンファレンスアプリに107個のPRがマージされました(一ヶ月間継続貢献)](https://zenn.dev/todayama_r/articles/55ddcb366cbc50)をご覧ください。

今年の目標は2つでした。

- 開催まで毎日かならずPRを1本以上出し続ける
- 当時不足していた、意味のあるIssueを100件以上つくる

目標は両方とも達成でき、Issueは最終的に(無効分を除いて)106件になりました。

# JVMアプリ開発に集中して見えたこと

去年はライブラリの都合で、コントリビュート期間の終盤になるまでapp-desktopモジュールを追加できず、JVMアプリも動かせませんでした([去年にゃふんたさんが四苦八苦して導入してくれたPR](https://github.com/DroidKaigi/conference-app-2024/pull/452))。今年は最初からapp-desktopを使える状態でした。ふだん触れないJVMアプリ開発に集中すれば得るものは大きいと考えて、ここを主戦場にしています(具体的に何を直したかは[このあたりのPR](https://github.com/DroidKaigi/conference-app-2025/pulls?q=is%3Amerged+is%3Apr+author%3ACorvus400+jvm+is%3Aclosed+)から追えます)。

たとえばAndroid開発ではまず見かけない[sun.misc.Unsafeというクラスが原因の問題](https://github.com/DroidKaigi/conference-app-2025/pull/362)に遭遇したのは新鮮でした。[compose-hot-reload](https://github.com/JetBrains/compose-hot-reload)も導入されていて、`hotRun --auto` で起動するとUIの変更がほぼリアルタイムに反映されます(物によっては反映されません)。実際の様子は[Composeへの変更が自動で反映されるツイート](https://x.com/Todayama_R/status/1961352052434501696)や[Compose Hot Reload Toolingが左側に表示されるツイート](https://x.com/Todayama_R/status/1961449932591976700)で見られます。

一方で、JVMはAndroidやiOSとは勝手が違う部分も多く、時間が足りずに解決しきれなかったことも残りました。

- [AndroidやiOSなら比較的かんたんに作れる、画像とテキストをまとめて共有する仕組みをJVMでどう実現するか](https://github.com/DroidKaigi/conference-app-2025/issues/581#issuecomment-3263171775)
- [Windowsで配布物からインストールする際に、証明書がないと出るUAC警告へ対応するには継続的な費用負担が必要になる](https://github.com/DroidKaigi/conference-app-2025/issues/342)
- [レスポンシブ対応がなく、Android/iOSのデザインをそのまま出すため大きすぎたり小さすぎたりするUIになる](https://github.com/DroidKaigi/conference-app-2025/issues/366)

最後のレスポンシブの件だけ統一的なIssueを立てていないと、記事を書きながら気づきました。基本的なところは今回ひととおり触ったので、来年のDroidKaigiでは残りに取り組みたいです。

# 普段使わないライブラリと基盤 (Metro / Soil / Navigation3)

このアプリは、ふだんのAndroid開発ではあまり選ばない技術で組まれていて、そこも学びになりました。

DIはふだんDagger Hilt(かDagger2)一択なので、[Metro](https://github.com/ZacSweers/metro)に触れたのはこのアプリが初めてです。MetroはZac Sweersさんが作る、Kotlin向けのコンパイル時DIフレームワークです。Data Layerも、ふだんはリポジトリを置く構成が一般的だと思います。今回は[Soil](https://github.com/soil-kt/soil)を使い、Android側ではリポジトリを介さない作りになっていて新鮮でした。Soilはクエリやフォームの状態をCompose向けにまとめたライブラリです。なお[iOS側はリポジトリ経由でDataStoreやWebAPIを扱う](https://github.com/DroidKaigi/conference-app-2025/tree/b92815ad621c88b3a921c274472c87813b1cebe6/app-shared/src/iosMain/kotlin/io/github/droidkaigi/confsched/repository)作りです。ナビゲーションのNavigation3も実務では未経験で、実際のコードを触ったのは今回が初めてでした。

[設定画面の実装](https://github.com/DroidKaigi/conference-app-2025/pull/288)と[そのテスト](https://github.com/DroidKaigi/conference-app-2025/pull/309)は、この3つをまとめて学ぶのにちょうど良いタスクでした。一方で苦労もしました。JVMで一部の画面遷移に不具合があり、直しはしたものの[あまりにワークアラウンドすぎる対応](https://github.com/DroidKaigi/conference-app-2025/pull/496)になってしまいました。根本原因は、JVMターゲットでNavEntryDecoratorの一部が使えないことでした。

ただ自分はNav3に不慣れで、NavEntryDecoratorの不足が原因という観点をそもそも持てませんでした。NavEntryDecorator自体は、kitakkunさんのPRを読むときにmikanさんの[LTスライド](https://speakerdeck.com/mikanichinose/navigation3teviewmodelnitetawodu-sufang-fa?slide=14)で知りました。mikanさんはカンファレンスアプリのスタッフをされている方です。最後はリードのkitakkunさんが[根本対応のPR](https://github.com/DroidKaigi/conference-app-2025/pull/504)を出してくれて、ようやく原因に気付けました。

# iOSで踏んだ落とし穴 (openURL / iPadOSのシェア)

ふだんiOSはあまり書かないので、今年はiOS側でも知らないことに2つぶつかりました。

## openURLがiOS 18で動かなくなっていた

[去年まで動いていたopenURLメソッドが今年は動かず、直したPR](https://github.com/DroidKaigi/conference-app-2025/pull/420)です。元のコードが使っていた[openURL(_:)](https://developer.apple.com/documentation/uikit/uiapplication/openurl(_:))は、去年の時点ですでにDeprecatedでした。ただ動いてはいたので問題になっていませんでした。Android Studio上でもDeprecatedの表記が出ず、ドキュメントを見に行かないと気付けない状態だったのです。

どうやらiOS 18から挙動が変わったようです。非推奨のコードを実行すると `BUG IN CLIENT OF UIKIT…Force returning false` がランタイムにログ出力されるのです。そしてメソッド自体が実行されなくなりました。この変更を裏づける公式の情報を探しましたが、辿り着けませんでした。

## iPadOSのシェアでアンカー未指定だとクラッシュする

[iOSでは動くのに、iPadOSではポップオーバーアンカーが未設定でクラッシュするコードを直したPR](https://github.com/DroidKaigi/conference-app-2025/pull/477)です。そもそも自分は[ポップオーバー](https://developer.apple.com/jp/design/human-interface-guidelines/popovers)という概念を知りませんでした。iPadでは[UIActivityViewController](https://developer.apple.com/documentation/uikit/uiactivityviewcontroller)がポップオーバーとして表示され、アンカーを指定しないとクラッシュしてしまいます。

クラッシュとは別件ですが、元のコードは[マルチシーン](https://techblog.lycorp.co.jp/ja/20250619a)に対応していませんでした。2画面の分割表示中にシェアが実行されると、keyWindowを取得できずnilになってクラッシュする状態だったと思います。変更後はとりあえず画面の中央にシェアウィンドウを出すようにしましたが、もう少し調整できる余地はありそうです。

# アニメーションをComposeで実装する

[今年のアニメーション導入PR](https://github.com/DroidKaigi/conference-app-2025/pull/480)についてです。[去年](https://www.figma.com/design/XUk8WMbKCeIdWD5cz9P9JC/DroidKaigi-2024-App-UI?node-id=54982-75775&t=gspaFDaToopEZ5hA-4)や[一昨年](https://www.figma.com/design/MbElhCEnjqnuodmvwabh9K/DroidKaigi-2023-App-UI?node-id=56145-55128&t=IDfBovd79230rxPg-4)のデザインは、Animated Vector Drawableとして扱いやすい構造でした([去年のアニメーション](https://github.com/DroidKaigi/conference-app-2024/pull/512)・[一昨年のアニメーション](https://github.com/DroidKaigi/conference-app-2023/pull/1176))。

ところが[今年](https://www.figma.com/design/1YjyMBNVLEGcHP4W7UNzDE/DroidKaigi-2025-App-UI?node-id=66492-10831&t=O6voqbHF42LXsZTc-4)は一体化した画像になっていて、例年のようにAVDでアニメーションを付けるのは無理でした。そこで今回は[androidx.compose.animation](https://developer.android.com/jetpack/androidx/releases/compose-animation?hl=ja)の機能でアニメーションを実装しました([Composeでのアニメーションのクイックガイド](https://developer.android.com/develop/ui/compose/animation/quick-guide?hl=ja)が参考になります)。

# 最後に

今年はプロジェクトのリードがtakahiromさんからkitakkunさんへ代わり、体制にも色々と変化があった年でした。慣れない立場で、[体調を崩しつつも尽力してくださった](https://x.com/kitakkun_pb/status/1961718357860012359)kitakkunさんには本当に感謝しています。mikanさんとkuwaさんも、日々の業務の合間にレビューなどで支えてくださり、ありがとうございました。

今年も短い期間でしたが、JVMや新しいライブラリ、iOSの落とし穴まで、ふだんの業務では出会えないことをたくさん学べました。来年もまた、今回できなかったところに挑戦したいです。同じようにカンファレンスアプリへ貢献してみたい方の、何かの参考になれば嬉しいです。
