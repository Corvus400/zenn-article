# 今回新しく出来たこと(一部抜粋)

## iOS側へのコントリビュート

2022年のカンファレンスアプリでは、Android側への貢献のみでした。今回も当初は、iOS側へのコントリビュートを考えていませんでした。しかし9月前の時点で着手可能なAndroidのIssueが枯渇し、iOS側のIssueが大量に残っていたのです。そこで、完遂可能だと予想されるIssueにチャレンジしてみることにしました。

普段は業務でAndroidコードのみを書いているため、最初はXcodeの操作にも不慣れで[環境の構築にも躓きました](https://twitter.com/Todayama_R/status/1697122495386489294)。OSS開発で時間が限られている中、一つ一つの疑問点を運営の方に聞くわけにもいきません。そこで今回はChatGPTを使用し、AndroidStudioで出来る種々の操作をXcodeでどう行うのか、環境構築で躓いた点はどこかを質問して、この関門を突破出来ました。

最初に選んだのは、[Android側で担当したTypographyの実装](https://github.com/DroidKaigi/conference-app-2023/pull/857)をiOS側でも同じように使えるようにするタスクです。これなら知識が少なくとも、諦めることなく完了させられると予想して取り組みました。残念ながら、Androidで実装したexpect/actualはiOS側で使用出来ないことが途中で判明しました。そこで通常のiOS開発のように、フォントをswiftgen(リソースをコードから型安全に扱えるよう自動生成するiOSのツール)でアプリから使える形に提供する方針へ転換し、[このタスクは完了出来ました](https://github.com/DroidKaigi/conference-app-2023/pull/1135)。

このタスクを終えた段階で「もしかしたら他のiOSタスクも、簡単なものなら出来るかも」という感触を得られました。そこでバグ修正なども行い、[無事マージされました](https://github.com/DroidKaigi/conference-app-2023/pulls?q=is%3Apr+author%3ACorvus400+iOS)。今回の貢献を通じて、モダンなiOS開発の知見を得られた事は非常に良質な学びでした。

## Animated Vector Drawableを使った見た目の向上

SplashScreenの実装を完遂する中で、時間が限られているため、素材の修正をデザイナーの方を待たずに自分でしなければならない場面が有りました。しかし[AVD](https://developer.android.com/guide/topics/graphics/drawable-animation?hl=ja)ファイル(ベクター画像にアニメーションを付与するAndroidの仕組み)をAndroidStudio上で手作業によって修正するのは、困難を極めました。XMLファイルではあるものの、中のパスの数値を手作業で直すのはほぼ不可能だからです。

そこでChatGPTへ質問したところ、[ShapeShifter](https://shapeshifter.design/)というサービスの存在を知りました。残念ながらSplashScreenの素材修正はこのサービスでは出来ませんでしたが、簡単なAVDファイルであれば自力で作成可能だと分かりました。元のデザイン仕様には存在しませんでしたが、以下二点を提案したところ、無事受け入れてもらえました。

1. [セッション詳細画面のブックマークボタンを押した際にAVDファイルを使い簡単なアニメーションを付ける](https://github.com/DroidKaigi/conference-app-2023/pull/1114)
2. [タイムテーブル画面上部で浴槽に浸かっているドロイド君を定期的に瞬きさせる](https://github.com/DroidKaigi/conference-app-2023/pull/1176)(X上でも[好評だった](https://twitter.com/Todayama_R/status/1701162937627652457)ようなので嬉しかったです)

Figmaで用意されているSVG素材の加工も行う必要が有ったため、これはInkscapeを使用しました。Inkscapeの操作も不慣れでしたが、操作方法はChatGPTへ質問して把握しました。今回の貢献を通じて、プログラマー側からもデザイン上の簡単な提案を行える道筋が見えました。

## Compose compiler metricsの導入とAndroidStudio上から簡単にレポート出力を可能にする

[他の貢献者の方によって修正されるまで](https://github.com/DroidKaigi/conference-app-2023/pull/1091)、スポンサー一覧画面のパフォーマンスが悪く、許容出来ないカクつきが発生していました。これを解決したいと考え、[このスライド](https://speakerdeck.com/moriatsushi/shi-li-karaxue-bujetpack-composenopahuomansugai-shan?slide=33)で紹介されていた[Compose compiler metrics](https://github.com/android/nowinandroid#compose-compiler-metrics)を導入しました。これはComposeのどの箇所が不要な再コンポーズの原因になりやすいかをコンパイル時に洗い出し、パフォーマンス改善の手がかりを与えてくれる仕組みです。

此方はNowinAndroidのREADMEに記載の通り、ターミナルでコマンドを実行するとレポートを出力出来ます。しかしコマンドを覚えておくのは非現実的で、毎回ドキュメントを見に行く必要が有って、使い勝手が悪いと感じていました。後日、他の貢献者の方の[このPR](https://github.com/DroidKaigi/conference-app-2023/pull/1162)の内容を見て応用出来るのではと予想し、実装したところ、AndroidStudioからGUI操作のみでレポートを出力出来るようになりました。このPRが無ければ、この方法の存在を知る事も自力で解決する事も出来なかったと思います。

今回の貢献を通じて、実業務でも応用可能な、runディレクトリのXMLファイルの作成方法と利用方法の知見を得られました。

## KMP(KotlinMultiplatform)開発の知見を深めた

[FigmaのTypography定義](https://www.figma.com/file/MbElhCEnjqnuodmvwabh9K/DroidKaigi-2023-App-UI?type=design&node-id=56041-40837&mode=design&t=JJpVCO7BKwIVA1bn-4)をAndroid/iOS両方で使用可能にするには、[expect/actual実装](https://kotlinlang.org/docs/multiplatform-connect-to-apis.html)が必要でした。これはKMPで、共通コード側に「期待する宣言(expect)」を置き、各プラットフォーム側に「実際の実装(actual)」を用意する仕組みです。2022年のカンファレンスアプリでは[androidMainにType.ktが存在していました](https://github.com/DroidKaigi/conference-app-2022/tree/main/core/designsystem/src/androidMain/kotlin/io/github/droidkaigi/confsched2022/designsystem/theme)。しかし2023年では[commonMainにType.ktが移っており](https://github.com/DroidKaigi/conference-app-2023/tree/main/core/designsystem/src/commonMain/kotlin/io/github/droidkaigi/confsched2023/designsystem/theme)、expect/actualでの実装が求められる事を、タスクに取り組んでから把握しました。

expect/actual実装に触れる機会は、DroidKaigi以前の業務でも有りました。ただ深く携わった事は無く、知見の乏しい状態でした。今回は[この記事](https://ishroid.medium.com/custom-font-loading-in-kmp-compose-multiplatform-2eb19865f61b)を参考にして実装出来ました。残念ながら、今回実装したTypographyのexpect/actual実装はiOS側で使用出来ませんでした。Composableアノテーションが付いているactualメソッドはスキップされ、[XCFramework](https://kotlinlang.org/docs/multiplatform-build-native-binaries.html#build-xcframeworks)で生成されるshared.swiftには含まれないためです。

それでも、KMPの開発手法そのものは学べました。Android側の実装をiOS側へ共有するには、[XCFrameworkのassemble定義をbuild.gradle.kts](https://github.com/DroidKaigi/conference-app-2023/blob/aeafd77f6aee5d402b811369126baac0064973d1/app-ios-shared/build.gradle.kts)に記述し、terminalからコマンドを実行します。共有されたコードは自動生成されたshared.swiftとして提供され、それをiOS側の必要な箇所でimportする事で、Kotlin側のコードをSwiftから呼び出せるようになります。今回の貢献を通じて、Kotlin側だけでなくiOS側で実際に使うとどうなるかを、デバッグしながら実装するための知見を得られました。

## 端末のLight/DarkモードによってMarkdownの画像を出し分ける

READMEの内容をもっと改善出来ないかとドキュメントを眺めていると、[prefers-color-scheme機能](https://docs.github.com/en/get-started/writing-on-github/getting-started-with-writing-and-formatting-on-github/basic-writing-and-formatting-syntax#specifying-the-theme-an-image-is-shown-to)を発見しました。これを応用すればREADMEトップの画像をLight/Darkモードで切り替えられて面白いと感じ、[これを提案したところ、無事受け入れられました](https://github.com/DroidKaigi/conference-app-2023/pull/1035)。今回の貢献を通じて、GitHubのMarkdownでは端末のLight/Darkモードによって画像を出し分けられる事を知れました。

# 最後に

DroidKaigiの運営の方々が作られた、素晴らしくモダンなアプリの骨子・デザイン。それによって今回のように一ヶ月という短期間で、モダンな(若しくは未来にデファクトスタンダードとなるであろう)開発の体験をする事が出来ました。また何よりも、過去および今回コントリビュートされた他の貢献者の方々の知見の偉大さを、大いに感じる事が出来ました。運営の方々、偉大なる他のコントリビューターの方々、Androidの素晴らしいドキュメント。これらの巨人の肩の上に立てた事が、今回の貢献を可能にしました。これらのどれが欠けても、今回の貢献は不可能でした。

これは個人の考えですが、DroidKaigiは開催前に公開されるプロジェクトへの貢献こそ、何よりも良質な学びを短期間で得られるまたとない機会だと考えています。カンファレンスで発表される資料は開催後も公開され続けているため、後から見る事も可能です。しかしプロジェクトへの貢献は、年に一度およそ一ヶ月間の期間限定でしか実行出来ません。まだ貢献した事が無い方も、是非ミニマムステップから始めてみては如何でしょうか？

私はこの一ヶ月間、とても充実した毎日を送る事が出来て楽しかったです。他のコントリビューターの方の貢献が更なる貢献を生む連鎖の加速感、そして最初は困難に思えた課題を乗り越えられた時の爽快感は最高です。勿論、全てが自力という訳ではなく、運営の方の懇切丁寧なレビューによって助けられた場面も幾多と存在します。この楽しみを、他の方々にも知ってもらいたいと切に思います。
